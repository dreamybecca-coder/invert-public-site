面向 Agent

我们发布的是能力，而不是一整排 Prompt。

INVERT 会把反复出现的投资研究任务，治理成少量清楚的 Capability。它必须先做到容易被发现、能够被验证、调用结果可预期，才会成为真正的公开工具。

目录预览

目前没有公开 API 或 MCP 服务。

01

对外的产品单位，是 Capability。

Skills 与方法是内部原料。Capability 只组合完成一个清楚任务所需的方法，并补上对外使用真正需要的证据、评测、权利与运行边界。

内部资产

Skills 与方法

原始分析流程、适配器、规则与检查清单。

↓
公开单位

Capability

稳定的任务、合同、证据模型与失败边界。

↓
用户体验

Product

Workbench、Agent 工具、工作流或独立应用。

02

三份公开合同，按成熟度逐层发布。

一项能力可以先被发现，再逐步走到可调用，但它当下的真实状态必须始终清楚。

01

发现合同

稳定身份、用户任务、适用与禁用场景、市场、语言、状态与 canonical URL。

谁应该在什么情况下找到它？
02

信任与证据合同

方法、来源、时效、覆盖范围、许可、评测、限制与版本变化。

人和 Agent 凭什么相信它？
03

调用合同

输入输出、接口、认证、价格、错误、延迟、隐私、留存、示例与支持。

Agent 能不能稳定而可预期地调用？

03

Capability 目录

下面是研究候选，不是产品上线声明。只有在真实任务评测、数据权利与运行证据都达标之后，它们的状态才会前进。

04 · 发布门槛

需求决定候选，证据决定能不能上线。

被问得多，并不自动等于值得做。它还必须可重复、具有差异、数据与许可可行、能够评测，并且值得承担相应的运行成本与责任。

需求 × 重复 × 差异 × 成熟度 ÷ 成本与风险
