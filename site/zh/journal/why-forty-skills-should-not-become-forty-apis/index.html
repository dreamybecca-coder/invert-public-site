为什么 40 个 Skills 不应该变成 40 个 API

内部方法不自动等于产品。公开能力应当从一个清楚的用户任务开始，再逐步获得证据标准、运行边界和调用合同。

2026年8月1日

内部方法不自动等于产品。如果把每个 Skill 都直接做成接口，只会把内部复杂度暴露出去，却不一定能带来更清楚的用户价值。

从用户任务开始

一项公开能力首先对应一个可以被识别的投资任务。随后，它才逐步获得稳定身份、证据标准、运行边界，以及真正准备好之后的调用合同。

  • 需求帮助我们发现任务，但不能证明能力有效。
  • 可信与证据先于 API 接口。
  • 内部 Skill 图谱可以复杂，外部接口必须清晰。

记录形成于真实实践，并会随着新的证据与复盘继续修订。
